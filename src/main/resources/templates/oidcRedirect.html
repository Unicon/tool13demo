    Step 1 of the launch

    Login initiation

    The LMS started this launch by sending the tool a login initiation request. The tool now identifies the LMS, creates a state and a nonce, and sends the browser back to the LMS to authenticate the user. In a production tool this page is invisible: it redirects immediately.

    What the LMS sent

    Received as form or query parameters on /oidc/login_initiations.

    iss
    The platform's issuer. Production Canvas sends https://canvas.instructure.com for every school.
    client_id
    The developer key (tool registration) on the LMS.
    lti_deployment_id
    Where the tool is installed (an account or course).
    login_hint
    Opaque to the tool. Sent back unchanged so the LMS knows which user this is.
    lti_message_hint
    Opaque to the tool. Identifies the link that was clicked. It expires after a few minutes.
    target_link_uri
    Where the user should end up once the launch completes.
    lti_storage_target
    The LMS offers storage for the cookieless flow (see below). The LMS doesn't support the cookieless flow, so the tool relies on a session cookie.

    What the tool created

    state
    SHA-256 hash of a signed state JWT that the tool stored server-side (with the nonce) for step 3.
    nonce
    Random, single use. It must come back inside the ID token.

    The authentication request

    The browser goes to the LMS's OIDC authorization endpoint with these parameters:

    client_id
    response_type
    response_mode
    scope
    prompt
    redirect_uri
    state
    nonce
    login_hint
    lti_message_hint
